# Telegram-бот (отдельное приложение)

Приём апдейтов Telegram вынесен из API в самостоятельное приложение: бот не
конкурирует с API за ресурсы, перезапускается независимо и работает строго в
одном экземпляре. Режим polling удалён полностью — канал только вебхук.

Логика не дублируется: обработка команд — это `app.services.telegram_bot` из
`../backend`, здесь только транспорт (проверка секрета, сессия БД, вызов
`handle_update`).

## Деплой на Timeweb

- Корень проекта: `smartweb/telegram-bot`
- Установка зависимостей: `pip install -r requirements.txt`
- Команда запуска: `./start.sh`
- Нужен публичный домен: Telegram обращается к `https://<домен>/webhook`
- Health-check: `GET /health`

Миграции здесь не запускаются — схему ведёт API (`smartweb/backend/start.sh`).

## Переменные окружения

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DATABASE_URL` | да | та же база, что у API |
| `TELEGRAM_BOT_TOKEN` | да | токен бота |
| `BOT_PUBLIC_URL` | да | публичный адрес ЭТОГО приложения, напр. `https://bot.example.com` |
| `APP_WEB_URL` | да | адрес веба для ссылок и кнопки Mini App |
| `TELEGRAM_BOT_USERNAME` | нет | имя бота без @ |
| `AI_GATEWAY_KEY` | нет | без него не работает `/ask` |
| `JWT_SECRET` | нет | нужен только админским ручкам `/admin/*` |
| `TELEGRAM_WEBHOOK_SECRET` | нет | если не задан, выводится из токена бота |

## Регистрация вебхука

Происходит автоматически при старте: приложение сверяет фактический URL из
`getWebhookInfo` с `BOT_PUBLIC_URL/webhook` и перерегистрирует при расхождении.
`setWebhook` идемпотентен и сам заменяет прежний адрес.

Вручную:
- `GET /admin/webhook-info` — что о вебхуке думает Telegram (нужен админский токен)
- `POST /admin/set-webhook` — принудительная перерегистрация
